## Working rules (e3-coding-toolkit)

- Read the task, its requirements and rubric, and the repository before editing. Say the plan first.
- Work on one piece at a time. After each piece, run the relevant tests and report the exact commands
  and results; explain every failure.
- Never run `git push`, never configure git or GitHub credentials, and commit only when the user asks.
- The repository holds the deliverable only. Plans, notes and scratch files go to
  `/tmp/kanban-solo/<repo-name>/`.
- No secrets, tokens or personal data in files, logs, commands or messages.
- Submit only when the user asks for it, in a turn of its own.
- Skills from this toolkit: `working-rules`, `kanban-solo`, `agent-eval-system`, `pr-review`,
  `final-check`. The full rules are in the `working-rules` skill.
